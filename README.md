# PARKAI — AI Visual Parking Finder

Find your car with a photo, not GPS. Save a picture of where you parked; later, upload a
picture of where you're standing, and the app matches it against a visual fingerprint of
every known parking spot.

```
PHOTO → AI VISION → VISUAL FINGERPRINT → SIMILARITY SEARCH → PARKING LOCATION
```

## Stack

- **Frontend**: React + TypeScript + Vite + Tailwind CSS + lucide-react
- **Backend**: FastAPI (Python)
- **Database**: SQLite via SQLAlchemy — schema and code are written so swapping to
  Postgres + pgvector is a config change, not a rewrite (see `backend/app/ai/search.py`)
- **AI**: Claude Vision when `ANTHROPIC_API_KEY` is set, otherwise a deterministic
  pixel-based fallback (color/shape heuristics, no trained model either way) — the
  app never breaks without a key. See "What's actually running" below.

## Screens

Home · Save my car (upload → AI Analysis → Fingerprint Created) · Find my car (upload →
AI Visual Search → ranked reveal) · Result (confidence ring, matched features, map) ·
Why this location (side-by-side landmark comparison) · Navigate (indoor route to the
spot) · Saved (your own saved spots) · AI Performance (benchmark + similarity chart) ·
How it works (plain-language explainer, linked from Home).

## Language

English, Russian, and Kazakh — switch with the **EN / RU / KK** pills in the top bar on
any screen (persisted to `localStorage`). Translation strings live in
`frontend/src/i18n/translations.ts` (typed so `ru`/`kk` can't silently drop a key the
`en` dict has). Landmark labels coming from the backend (`"Blue column"`, `"Elevator"`,
etc.) are translated separately in `frontend/src/i18n/landmarks.ts` against the
backend's known fixed vocabulary — anything outside that set (e.g. real Claude Vision
free text) is shown as-is rather than mistranslated.

## Run it

**Backend** (FastAPI on port 8000):

```bash
cd backend
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python -m app.seed.generate_dataset   # seeds 48 demo parking locations + images
uvicorn app.main:app --reload --port 8000
```

**Frontend** (Vite on port 5173, proxies `/api` and `/static` to the backend):

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`. Click **TRY DEMO** on the home screen for a scripted
one-click walkthrough of the full flow (save → search → 94%+ match → why-this-location).

To test Save/Find manually with real uploads instead, `test-photos/` has two ready-made
pairs (`1_save_spot_B03.jpg` + `2_find_car_B03.jpg`, and the same for `D02`).

## Enabling real AI vision

Without an API key, floor/zone/spot-number reading falls back to color-blob heuristics
(no OCR), so exact-spot precision on arbitrary photos is honest-but-limited. Set an API
key before starting the backend to enable real vision-based sign reading:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

`GET /api/health` reports `ai_vision_enabled` so you can confirm which mode is active.

## What's actually running: AI or ML?

Neither, by default. Without an API key, `vision.py`'s `_heuristic_cv()` (color-area
voting against 4 reference zone colors, brightness for floor) and `embedding.py`'s
tiny-grayscale + color-histogram vector are both plain pixel arithmetic — no learned
weights, nothing trained. Set `ANTHROPIC_API_KEY` and it becomes real **AI**: Claude's
vision model actually reads the photo's signage and describes landmarks. There is no
custom-trained **ML** model anywhere in this project in either mode — that was a
deliberate scope decision, not an oversight.

## How the matching works

1. **Vision** (`backend/app/ai/vision.py`) turns a photo into structured landmarks
   (`{type, value, confidence}`) plus a floor/zone/number guess.
2. **Embedding** (`backend/app/ai/embedding.py`) turns the photo into a pure pixel
   vector (grayscale layout + color histogram) — this is what a vector index would
   store and search.
3. **Search** (`backend/app/ai/search.py`) ranks all locations by cosine similarity,
   then blends in an explicit landmark-match ratio (also what powers the "why this
   location" matched-features checklist) for the final confidence score.

Landmarks are deliberately kept out of the embedding vector itself — folding a
variable-length feature list into one vector made cosine similarity penalize
locations for having *more* detected landmarks than the query, which is backwards.
Keeping them as a separate, explicit comparison fixed that and doubles as the UI's
explanation feature.

## Demo dataset & benchmark

48 synthetic (but structurally realistic) garage-photo locations across 2 floors × 4
zones × 6 spots, generated by `backend/app/seed/generate_dataset.py`. The AI Performance
page (`/#/analytics`) runs a held-out 20-photo benchmark and clearly labels itself a
**Demo benchmark** — it's a real accuracy measurement against the fallback heuristic,
not a fabricated number.
